# Prompt Store

Manage app-scoped templates. Prompt content remains live independently of QuilrQL; `prompts.require_system_from_store` controls enforcement in app configuration.

| Input | Contract |
| --- | --- |
| App locator | Encoded app-name path, or `/app/prompts?...` with `app_name` in the query. |
| `prompt_id` | 1-200 characters: letters, digits, hyphens and underscores. |
| `content` | Nonempty template string. The complete JSON body must fit within 1 MiB. |
| Every mutation | Current **app** ETag in `If-Match`, including creation. |

PUT creates a missing prompt (`201`) or replaces an existing prompt (`200`). It preserves other prompts/settings. Create-only prompt preconditions are **Not Generally Available**; `If-None-Match` is not implemented as a create-only guard. DELETE returns `200` with `prompt:null`, `prompt_id`, the updated app `version` and `request_id`.

Reads return prompt content and the current app version. A change to any versioned app setting can invalidate a prompt-write precondition. Re-read before reconciling `412` conflicts.

```json
{
  "content": "You help customers with support questions. Use supplied account context and do not invent account details."
}
```

Prompt content is visible to keys with `read`. For runtime references and variables, see [Prompt Store](../features/prompt-store).
