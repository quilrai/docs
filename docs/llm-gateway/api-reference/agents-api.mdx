# Agents API

Read the agents the LLM Gateway has seen in the last 30 days, **declare** the ones you know with an owner and tags, and gather agents into **agent groups**. The same data appears on the **Agents** tab under **Govern > Policy Engine > LLM Gateway** in the console. See [Agents and coding tools](../protect/agents-and-coding-tools) for how the gateway identifies agents.

:::warning Agent identity is a label
Agents are identified from what the client sends (`x-quilr-agent-id` and related headers, request metadata, W3C baggage or a detected coding tool such as Claude Code). A caller can send any id, so treat an agent as a label, never as authentication.
:::

| Call | What it does | Scope |
| --- | --- | --- |
| `GET /agents` | List agents seen in the last 30 days and every declared agent. | `read` |
| `POST /agents/_declare` | Declare up to 500 agents at once with the same owner and tags. | `agents:write` |
| `GET /agents/{key}` | Read one agent. | `read` |
| `PUT /agents/{key}` | Declare an agent, or replace its declaration. | `agents:write` |
| `PATCH /agents/{key}` | Change some fields of a declared agent. | `agents:write` |
| `DELETE /agents/{key}` | Remove a declaration. The agent stays listed while it appears in traffic. | `agents:write` |
| `GET /agent-groups` | List built-in and custom agent groups. | `read` |
| `GET /agent-groups/{group_id}` | Read one group. | `read` |
| `PUT /agent-groups/{group_id}` | Create or replace a group. | `agents:write` |
| `PATCH /agent-groups/{group_id}` | Change some fields of a group. | `agents:write` |
| `DELETE /agent-groups/{group_id}` | Delete a group. | `agents:write` |
| `GET /agent-groups/{group_id}/members` | List a group's current members and how each one matched. | `read` |
| `GET /agent-families` | List families with their surfaces and 30-day counts. | `read` |

Every path is relative to `https://<your-gateway-host>/llmgateway/management/v1` and takes `Authorization: Bearer <management key>`. Bodies and responses are snake_case JSON. Issue a key with the **Manage agents** scope (`agents:write`) on the console **Management API** tab, like the other scopes; see [Management API](./management-api#enable-in-the-console).

## Agent keys {#agent-keys}

An agent key is `<family>/<id>`, for example `custom/agent_7xC` or `claude_code/subagent`. The family is lower-case letters, digits and `_`. The id keeps letters, digits, `-`, `.` and `_` and percent-encodes everything else. A key is at most 320 characters; a very long id gets a hashed key `<family>/~h.<hash>`, which can be declared.

`<family>/~<surface>` and `<family>/~any` (for example `claude_code/~cli`) name a **detected client** that sent no agent id. They are listed and can go in a group, but declaring one answers `422 agent_key_family_only`.

In a path, URL-encode the key: `custom%2Fagent_7xC`.

## Agents {#agents}

```bash
export API="https://<your-gateway-host>/llmgateway/management/v1"

curl "$API/agents?status=observed&family=custom&limit=50" \
  -H "Authorization: Bearer $MANAGEMENT_KEY"
```

`GET /agents` lists agents most recently active first. Filters:

| Query | Meaning |
| --- | --- |
| `q` | Text in the key, name or owner. |
| `family` | Only this family (`custom`, `claude_code`, ...). |
| `status` | `declared` or `observed`. |
| `group` | Only members of this agent group (`422 agent_group_unknown` if no group has that id). |
| `app` | Only agents seen under this application. |
| `limit`, `cursor` | Page size (1-500, default 100) and the `next_cursor` of the previous page. |

The response is `{agents, total, next_cursor, registry_version, observed_available, observed_complete, window_days}`. `next_cursor` is present only when another page exists. `observed_available` is `false` where traffic can't be read; declared agents are still listed. `window_days` is `30`.

| Agent field | Meaning |
| --- | --- |
| `key`, `family`, `surface`, `id` | The agent key and its parts. `surface` is set for family rows and subagents, for example `cli`. |
| `name`, `observed_name` | The display name (the declared one when set) and the name the client sent. |
| `status` | `declared` or `observed`. |
| `owner`, `description`, `tags` | From the declaration; `null` / empty when not declared. `owner` is a label only and never changes who a request is charged to. |
| `groups` | Ids of the agent groups it is in now. |
| `apps` | Applications it was seen under in 30 days. |
| `first_seen`, `last_seen`, `requests_30d`, `users_30d` | 30-day activity. `users_30d` is `null` when not yet known. |
| `version`, `updated_at`, `updated_by` | Declared agents only. Send `version` as `If-Match`. A Management API write is recorded as `management_key:<key_id>`. |

```json
{
  "key": "custom/agent_7xC",
  "family": "custom",
  "surface": null,
  "id": "agent_7xC",
  "name": "FinSight Auditor",
  "observed_name": "FinSight Auditor",
  "status": "declared",
  "owner": "finance-platform@example.com",
  "description": null,
  "tags": ["finance"],
  "groups": ["all-agents", "finance-agents"],
  "apps": ["zz-docs-finance"],
  "first_seen": "2026-10-21T08:00:00Z",
  "last_seen": "2026-11-19T07:58:00Z",
  "requests_30d": 1240,
  "users_30d": 5,
  "version": "3f1c...",
  "updated_at": "2026-11-19 08:00:00.000",
  "updated_by": "management_key:mk_example"
}
```

`GET /agents/{key}` returns `{agent, registry_version}`, or `404 agent_not_found` when the key was neither declared nor seen in 30 days.

## Declare agents {#declare}

Declare one agent with `PUT`:

```bash
curl -X PUT "$API/agents/custom%2Fagent_7xC" \
  -H "Authorization: Bearer $MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"display_name": "FinSight Auditor", "owner": "finance-platform@example.com", "tags": ["finance"]}'
```

- **`PUT /agents/{key}`** takes `display_name`, `owner`, `description` and `tags` (up to 20) and replaces the whole declaration. It answers `201` for a new declaration and `200` for a replaced one, with `{agent, registry_version, applies_within_seconds}`. Any well-formed key can be declared, seen or not; a key with no traffic in 30 days adds the warning `agent_not_seen` under `warnings`.
- **`PATCH /agents/{key}`** changes only the fields you send; `null` clears one. It answers `404 agent_not_declared` when the agent is not declared yet.
- **`DELETE /agents/{key}`** removes the declaration and answers `{deleted: true, key, registry_version}`. The agent stays listed as `observed` while it appears in traffic.
- **`POST /agents/_declare`** declares 1-500 keys at once: `{"keys": [...], "owner": "...", "tags": [...]}` (`display_name` and `description` are accepted too). Keys already declared are left as they are. The response is `{declared, already_declared, registry_version}`.

```json
{"keys": ["custom/agent_7xC", "custom/invoice_extractor"], "owner": "finance-platform@example.com", "tags": ["finance"]}
```

## Agent groups {#agent-groups}

`GET /agent-groups` returns `{agent_groups, registry_version, limits}`, built-in groups first. The built-in groups are computed by the gateway and read only (`409 builtin_group_read_only`):

| `id` | Members |
| --- | --- |
| `all-agents` | Every agent that is named. Family rows (`<family>/~<surface>`) are not members. |
| `undeclared-agents` | Agents seen in traffic that nobody has declared. |
| `coding-tools` | Detected coding-tool families such as Claude Code, Codex and OpenCode. |

Create or replace a group with `PUT /agent-groups/{group_id}`. The id is 1-64 lower-case letters, digits, `-` and `_`.

```bash
curl -X PUT "$API/agent-groups/personal-agents" \
  -H "Authorization: Bearer $MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"display_name": "Personal agents", "exclude_keys": ["custom/support_triage"], "match": {"families": ["custom"], "max_users_30d": 1}}'
```

| Group field | Meaning |
| --- | --- |
| `display_name`, `description` | What the console shows. |
| `keys` | Agent keys that are always members. Family rows may be listed. |
| `exclude_keys` | Keys that are never members. An exclusion beats `keys` and `match`. |
| `match` | Rules that add agents automatically, below. |
| `id`, `builtin`, `version`, `updated_at`, `updated_by` | Returned on reads. Send `version` as `If-Match`. |

| `match` field | Matches |
| --- | --- |
| `families` | A family (`claude_code`) or a family and surface (`claude_code/desktop`). |
| `surfaces` | A surface such as `cli`, `desktop` or `subagent`. |
| `name_globs`, `id_globs` | Case-insensitive patterns on the agent name (`"KYC *"`) or id (`"agent_*"`). |
| `apps`, `app_tags` | Application names (patterns allowed) the agent was seen under, or their tags. |
| `tags` | Tags set when the agent was declared. |
| `declared` | `true`, `false` or `null` (either). |
| `max_users_30d` | At most this many people in 30 days. An agent with no people figure yet never matches. |

Every `match` field you send must hold (AND); any value in one list may match (OR). A group with no `keys` and an empty `match` has no members. Membership is worked out on every request, so a new agent joins on its first request.

- `PUT` answers `201` for a new group and `200` for a replaced one, with `{agent_group, registry_version, applies_within_seconds}`.
- `PATCH` changes only the fields you send; `404 agent_group_not_found` when the group does not exist.
- `DELETE` answers `{deleted: true, id, registry_version}`.

Limits: 200 groups per organization, 5,000 keys per group, 50 `name_globs` and `id_globs` combined per group, and an agent counts in at most 64 groups.

### Members {#members}

`GET /agent-groups/{group_id}/members` (with `limit` and `cursor`) returns `{members, total, next_cursor, observed_available, registry_version}`. Each member is `{key, name, family, status, last_seen, matched_by}`, where `matched_by` is `key` (listed), `match` (a match rule) or `builtin`. A listed key that was never seen or declared has `status: "not_seen"`.

```json
{
  "members": [
    {"key": "custom/agent_7xC", "name": "FinSight Auditor", "family": "custom", "status": "declared", "matched_by": "match", "last_seen": "2026-11-19T07:58:00Z"}
  ],
  "total": 1,
  "observed_available": true,
  "registry_version": 1763539200000
}
```

## Agent families {#families}

`GET /agent-families` returns every family the gateway recognizes with its surfaces and 30-day counts:

```json
{
  "agent_families": [
    {"family": "claude_code", "agents_30d": 2, "requests_30d": 50210,
     "surfaces": [{"surface": "cli", "agents": 2, "requests_30d": 48000}]}
  ],
  "observed_available": true,
  "window_days": 30
}
```

## Writes and errors

- `PUT`, `PATCH` and `DELETE` take an optional `If-Match: "<version>"` with the `version` a read returned. A stale version answers `412 version_conflict`.
- Writes are audited and reach every gateway server within `applies_within_seconds` (about 2 minutes).
- Writes run on the central gateway service only.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_request` | The body is not a JSON object, or a query value (`status`, `limit`, `cursor`) is not valid. |
| `403` | `insufficient_scope` | The key lacks `read` (reads) or `agents:write` (writes). |
| `404` | `agent_not_found` | The agent was neither declared nor seen in 30 days. |
| `404` | `agent_not_declared` | `PATCH` or `DELETE` of an agent that is not declared. |
| `404` | `agent_group_not_found` | No group has this id. |
| `409` | `builtin_group_read_only` | A write to a built-in group. |
| `409` | `agent_group_limit` | The organization already has 200 groups. |
| `412` | `version_conflict` | `If-Match` is stale. Read again and retry. |
| `422` | `agent_key_invalid` | The key is not `<family>/<id>`. |
| `422` | `agent_key_family_only` | A family key (`<family>/~<surface>`) was declared. |
| `422` | `agent_group_unknown` | `GET /agents?group=` names no group. |
| `422` | `validation_failed` | An unknown field, a bad group id, too many tags, keys or patterns, or a value of the wrong type. `field` names it. |
| `503` | `central_service_required` | A write on an isolated deployment. Make the change on the central service. |
| `503` | `management_storage_unavailable` | The change could not be saved. Retry. |
