# Smart groups API

Read the smart groups the LLM Gateway uses, create **virtual groups** with a fixed member list, and set the **rank** that decides which group governs a person who is in several groups. The same groups appear in the **Groups** section of **Govern > Policy Engine > LLM Gateway** in the console.

:::note Rank, strength and the API fields
The console **Rank** column is the API field **`priority`**: the number you edit, where a lower number wins. The console **Strength** column (**#1** is the strongest) is the API field **`rank`**: a computed position you cannot set.
:::

| Call | What it does | Scope |
| --- | --- | --- |
| [`GET /smart-groups`](#List_smart_groups), [`GET /smart-groups/{group_name}`](#Read_a_smart_group) | List or read groups with members, `priority` and `rank`. | `read` |
| [`POST /smart-groups`](#Create_a_virtual_smart_group) | Create a virtual group. | `config:write` |
| [`PATCH /smart-groups/{group_name}`](#Update_a_smart_group) | Edit a virtual group, or override a synced group's rank (`priority`). | `config:write` |
| [`POST /smart-groups/{group_name}/members`](#Change_smart_group_members) | Add or remove members of a virtual group without replacing the list. | `config:write` |
| [`DELETE /smart-groups/{group_name}`](#Delete_a_virtual_smart_group) | Delete a virtual group. | `config:write` |
| [`POST /smart-groups/_priority-preview`](#Preview_smart_group_priorities) | See who would change governing group, and which budgets they would switch, before you save a `priority`. No writes. | `read` |

Try every operation with your own key in the [Management API playground](/llm-gateway-management-playground?tab=explorer).

## Rank and the governing group {#rank}

Every group has a rank number, the **`priority`** field (console **Rank**). A lower number is stronger. When a person is in several **enabled** groups, the group with the lowest priority is their **governing group**; equal priorities are ordered by group name. Disabled groups never govern anyone.

- **`rank`** (console **Strength**) is computed from that order: the group's 1-based position among enabled groups, `1` being the strongest. It is `null` for a disabled group. You never send it; change `priority` instead.
- The governing group decides whose guardrails apply to the person (per-group app settings, `smart_group_policies`), and which budget applies in a [group budget set](./budgets-api#group-budget-sets) that uses the strongest group's budget.
- Lists are returned strongest first.

## Synced and virtual groups {#synced-and-virtual}

| | Synced groups | Virtual groups |
| --- | --- | --- |
| Where they come from | Your organization's [Smart Groups](../../console/settings-organization/smart-groups) and directory, kept up to date by a sync. | Created in the console **Groups** tab or with `POST /smart-groups`. |
| Name | The synced name. | Stored as `virtual:<name>`. The console shows the name without the prefix and a **Virtual group** label. Use the full name in policy conditions and budgets. |
| Members | Managed by the sync. | A fixed list of emails you manage. The sync never changes or deletes a virtual group. |
| What you can change here | Only the rank, as a `priority` override. | Display name, members, enabled state and rank (`priority`). |

**Rank override.** A synced group's `priority` is set by the sync (by default the groups are ordered by name). Send `PATCH {"priority": n}` to override it. The override survives every later sync. Send `{"priority": null}` to reset to the synced value. Reads show both: `priority` is the value in effect, `synced_priority` is the sync's value and `priority_override` is your override (or `null`).

## Group fields

| Field | Meaning |
| --- | --- |
| `group_name` | Full name; virtual groups start with `virtual:`. Use it in the path. |
| `name` | Name without the `virtual:` prefix. |
| `display_name`, `emails`, `member_count`, `enabled` | What the group shows and who is in it. |
| `priority` | The editable rank number (console **Rank**) in effect: the override when set, else the synced value. Lower wins. |
| `synced_priority`, `priority_override` | The sync's priority (a virtual group's own priority) and the admin override (`null` when none). |
| `priority_override_updated_at`, `priority_override_updated_by` | When and by whom the override was last set or reset. A Management API write is recorded as `management_key:<key_id>`. |
| `source` | `synced` or `virtual`. |
| `rank` | Computed 1-based position among enabled groups (console **Strength**); `null` when disabled. Read only. |
| `version` | Send it as `If-Match` on `PATCH`, `DELETE` and the members call. |

## Create and edit virtual groups

```bash
export API="$MANAGEMENT_URL/llmgateway/management/v1"

curl -X POST "$API/smart-groups" \
  -H "Authorization: Bearer $MANAGEMENT_KEY" \
  -H "Idempotency-Key: create-sales-leads" \
  -H "Content-Type: application/json" \
  -d '{"name": "sales leads", "display_name": "Sales leads", "emails": ["ana@example.com", "li@example.com"], "priority": 10}'
```

- **Create** takes `name` (required), `display_name` (default: the name), `emails`, `enabled` (default `true`) and `priority` (default `100`). The name is lowercased with spaces collapsed, up to 200 characters; `priority` is reserved. The response (`201`) is `{"smart_group": {...}}` with `group_name: "virtual:sales leads"`.
- **Edit** with `PATCH` changes only the fields you send. `emails` replaces the whole list. Priorities are whole numbers from `0` to `1000000`.
- **Change members** with `POST /smart-groups/{group_name}/members` and `{"add": [...], "remove": [...]}` (at least one email; an email cannot be in both). Emails already present or already absent are ignored. The response is `{smart_group, added, removed}`, where `added` and `removed` count actual changes.
- **Delete** answers `409 group_in_use` with `references` (up to 50) when the active policy, budgets, exemptions, API-managed controls or app settings still name the group. Remove the references, or send `?force=true` to delete anyway; the response then lists them in `forced_references`. Drafts are not checked.

Emails match case-insensitively and are stored lowercase.

## Preview a rank change {#priority-preview}

Before saving a `priority`, send the changes to `POST /smart-groups/_priority-preview`. Nothing is saved.

```json
{"changes": [{"group_name": "executives", "priority": 1}, {"group_name": "virtual:sales leads", "priority": 20}]}
```

| Response field | Meaning |
| --- | --- |
| `affected_users`, `affected_count`, `truncated` | People whose governing group would change (`email`, `from_group`, `to_group`), the first 500, and the total. |
| `ties` | Ties the change creates: a `priority` that a moved group would share with another enabled group that has members in common (`shared_members`). Existing ties the change does not touch are not listed. Tied groups are ordered by name; give them distinct priorities to be explicit. |
| `budget_moves`, `budget_moves_count`, `budget_moves_truncated` | People whose governing budget would change in a group budget set that uses the strongest group's budget: `set_id`, `set_label`, `from_group`, `to_group`, the budget ids and, when known, `metric`, `window`, `from_limit` and `to_limit`. `apps` lists the apps where the move happens (`"*"` means every other app) and is `null` when it happens everywhere. In sets with app-scoped budgets the governing group can depend on the request: `conditional` is then `true` and `from_groups` / `to_groups` list the possible groups. |
| `budget_moves_unavailable` | Set when budgets could not be read; `budget_moves` is then empty. |

A person who moves starts counting in the new group's budget from zero; their earlier usage stays on the old group's budget. Send `null` as the priority to preview a reset to the synced value (synced groups only). Up to 1,000 changes per preview.

## Writes and errors

- `POST /smart-groups` and the members call need an `Idempotency-Key`; a retry with the same key replays the first result.
- `PATCH` and `DELETE` need `If-Match` with the group's `version` (`428` without it, `412 version_conflict` when stale). `If-Match` is optional on the members call.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_request` | A field has the wrong shape, a priority is out of range, or `null` was sent for a virtual group. |
| `404` | `not_found` | The group does not exist (also when it was deleted at the source). |
| `409` | `smart_group_exists` | A group with this name already exists. |
| `409` | `synced_group_read_only` | A field other than `priority` was sent for a synced group, or a synced group was deleted or given members. |
| `409` | `group_in_use` | The group is still referenced; see `references`. |
| `409` | `idempotency_outcome_unknown` | The group changed after a failed attempt with this key. Read it and retry with a new key. |
| `503` | `smart_group_storage_unavailable`, `reference_check_unavailable` | Storage or the reference check is unavailable. Retry. |
