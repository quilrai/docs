# Connections and OAuth API

Check whether an MCP is serving tools, fetch its tools now, and connect OAuth MCPs created through the API.

## Connection state {#connection-state}

`GET /mcps/{mcp_id}/connection` returns `connection_state`:

| State | Meaning |
| --- | --- |
| `ready` | Tools are cached and served. |
| `pending_connection` | An OAuth MCP waiting for its OAuth connection. Issue a [connect link](#connect-links). |
| `fetch_failed` | The last tool fetch failed. `last_fetch_errors` has fixed codes: `auth_failed`, `timeout`, `tls_error`, `unreachable`, `protocol_error`, `no_capabilities` or `unknown`. |
| `pending_first_client` | An OAuth passthrough MCP: tools appear when the first client connects with its own token. |

The response also lists `connected_admins`, the administrators with an OAuth connection to the MCP.

## Refresh tools {#refresh}

`POST /mcps/{mcp_id}/capabilities:refresh` (scope `mcps:write`) fetches tools, resources and prompts from the upstream server now, as the administrator who issued the key, and replaces the cached lists. New tools may be held for review (`held_tools`); see [tool reviews](./settings-and-credentials-api#tool-reviews).

| Response | Meaning |
| --- | --- |
| `409 oauth_connection_required` | The OAuth MCP has no connection for the key's administrator. Issue a [connect link](#connect-links). |
| `409 upstream_credential_required` | The MCP needs a credential before tools can be fetched. Set one with [upstream credentials](./settings-and-credentials-api#upstream-credentials). |
| `409 pending_first_client` | OAuth passthrough MCPs cannot be refreshed by the gateway. |

## Connect links {#connect-links}

An OAuth MCP (`auth.type` `oauth_dcr` or `oauth_login`, or an OAuth catalog MCP) needs one OAuth sign-in with the provider before the gateway can fetch its tools. A connect link lets you finish that sign-in from a browser, without the console.

<StepFlow steps={[
  {label: 'Create', items: ['OAuth create or install', 'or POST connect-links']},
  {label: 'Share', items: ['Single-use link', 'Valid 15 minutes']},
  {label: 'Open', items: ['No Quilr sign-in', 'Provider sign-in']},
  {label: 'Ready', items: ['Connection saved', 'Tools fetched']},
]} />

1. Create the OAuth MCP (`POST /mcps` with `auth.type` `oauth_dcr` or `oauth_login`, or install an OAuth catalog MCP). The response contains a `connect` object with a single-use `url` that is valid for 15 minutes and its `expires_at`. `POST /mcps/{mcp_id}/connect-links` issues a new link at any time.
2. Open the link in a browser, or send it to the person who should complete the provider sign-in. No Quilr sign-in is needed: whoever opens the link is sent to the provider's sign-in. The link's token is in the URL fragment, so the browser never sends it in the page request or to server logs, and the page removes it from the address bar at once.
3. The page starts the provider's sign-in. After consent, the gateway saves the connection for the administrator who issued the management key, fetches the tools and shows a success page.
4. `GET /mcps/{mcp_id}/connection` then reports `ready` and lists that administrator in `connected_admins`.

```bash
curl --request POST "$GW/mcpgateway/management/v1/mcps/e5f6a7b8/connect-links" \
  --header "Authorization: Bearer $KEY"
```

```json
{
  "mcp_id": "e5f6a7b8",
  "connect": {
    "url": "https://mcpgateway.example.com/mcpgateway/management-connect#t=<token>",
    "expires_at": "2026-11-14T10:15:00Z"
  },
  "request_id": "8d0f6c1e2a4b4c9d9e7f1a2b3c4d5e6f"
}
```

:::warning Treat a connect link like a password
A connect link is a bearer credential for 15 minutes and can be used once. Whoever opens it first connects *their* provider account, and that connection is saved for the administrator who issued the management key. Share the link only with the person who should connect, over a private channel, and issue a new link if it may have leaked. An unused link stops working when it expires, when it is used, or when the issuing management key is revoked or expires.
:::

End users connect with their own accounts later, as with MCPs added in the console. See [OAuth connect](../servers-and-connections/oauth-connect). OAuth passthrough MCPs need no link.

### How the connect page works {#connect-page}

The connect page sends the token to `POST /mcpgateway/management-connect/start` with the body `{"token": "<t>"}`. This endpoint takes no authentication and is rate limited per client address. It answers `mcp_id`, `mcp_name`, `authorization_url` and `request_id`, and the page then opens `authorization_url`. You do not need to call it yourself; errors use the normal [error shape](./management-api#errors).

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `invalid_request` | Missing or malformed `token`, or extra fields. |
| 403 | `management_disabled_for_tenant` | Management is turned off for the organization. |
| 404 | `connect_link_not_found` | Unknown link, or its MCP was removed. |
| 409 | `connect_link_used` | The link was already used. Issue a new one. |
| 409 | `key_owner_unavailable` | The key's administrator left the organization. Issue a new key and link. |
| 409 | `oauth_not_applicable` | The MCP no longer uses gateway-managed OAuth. |
| 410 | `connect_link_expired` | The link is older than 15 minutes. Issue a new one. |
| 410 | `connect_link_revoked` | The management key that issued the link was revoked or expired. |
| 429 | `rate_limited` | Too many attempts from this address. Retry after `Retry-After`. |
| 502 | `oauth_initiation_failed` | The provider sign-in could not be started; the link was not used. |

`POST /mcps/{mcp_id}/connect-links` answers `409 oauth_not_applicable` for an MCP that does not use gateway-managed OAuth.

Retrying an OAuth create with the same `Idempotency-Key` within 24 hours returns the same connect link.
