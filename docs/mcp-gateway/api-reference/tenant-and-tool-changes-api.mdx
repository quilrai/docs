# Tool changes and tenant API

Try these operations with your own key in the [MCP Management API playground](/mcp-gateway-management-playground?tab=tenant).

## Tool changes {#tool-changes}

The tool watch compares each MCP's upstream tool list with the cached one. `GET /tool-changes` returns one row per MCP (`pending_only=true` for those with a change awaiting review), and `GET /mcps/{mcp_id}/tool-changes` one MCP with the tools `added`, `removed` and `modified` upstream. What happens on a change depends on the MCP's `tool_sync` setting (`notify`, `auto` or `off`).

| Operation | Effect |
| --- | --- |
| `POST /mcps/{mcp_id}/tool-changes/check` | Compare with the upstream list now. |
| `POST /mcps/{mcp_id}/tool-changes/apply` | Replace the cached tool list with the upstream one. New tools may still be held for [review](./settings-and-credentials-api#tool-reviews). |
| `POST /mcps/{mcp_id}/tool-changes/dismiss` | Keep the cached list and stop flagging this upstream list. A different upstream list opens a new change. |

Apply and dismiss answer `409 no_pending_tool_changes` when nothing is awaiting review. These need `tool_reviews:write`. A failed check reports a fixed `reason_code` (for example `auth_failed` or `unreachable`), never upstream text.

`GET /mcps/{mcp_id}/oauth-scope-options` lists the permission bundles the provider offers for an OAuth MCP and the stored selection. Select bundles with `oauth_scopes` in the MCP's [settings](./settings-and-credentials-api).

## Tenant settings {#tenant-settings}

`GET /tenant/settings` returns the organization switches, each with who changed it last:

| Section | Field | Meaning |
| --- | --- | --- |
| `smart_mode` | `mode` | Dynamic Tool Calling for OneMCP: `user_preference` (each user chooses), `force_enabled` or `force_disabled`. |
| `memories` | `enabled` | Memories for users and OneMCP. |
| `tool_review` | `hold_new_tools` | Hold new upstream tools for review on every MCP that inherits the organization default. |

`PATCH /tenant/settings` changes any of the sections. It needs `tenant_settings:write` and `If-Match` with the `version` from the read. The response also shows the data-retention policy revision, which is managed in the console, and whether QuilrQL policies govern the organization (`policy_authority.mode`); under QuilrQL the switches are stored but the policies decide.

## Tool-argument aliases {#aliases}

An alias rewrites the arguments clients send before a call reaches the MCP: a parameter rename (`kind: param_alias`, `from`, `to`) or a value normalization (`kind: value_normalization`, `param`, `from_values`, `to_value`), for one tool. `POST /tool-arg-aliases` with `{"mcp_id", "spec"}` adds one after checking it against the tool's input schema (`400` when it does not fit). `GET /tool-arg-aliases` lists them (filter with `mcp_id` and `tool_name`); `active` is false when an alias is disabled or no longer fits the tool's current schema. `PATCH` changes `enabled` and `note`; `DELETE` removes one. Writes need `tenant_settings:write`.

## MCP requests {#mcp-requests}

Users can ask for an [MCP Library](./mcps-api#catalog) entry from their dashboard. `GET /mcp-requests` lists pending requests, newest first, with what installing each entry needs. Installing the entry (`POST /catalog/{catalog_id}/install`) fulfils every pending request for it. `POST /mcp-requests/{request_id}/dismiss` dismisses one request (`tenant_settings:write`).
