# Settings and credentials API

Change how the gateway serves each MCP: its tools, DLP, token saving, access control and other settings, overrides for one user or smart group, the credentials the gateway sends upstream, and which new tools clients can see.

Every write on this page needs `If-Match` with the MCP's current `version` (see [versions and If-Match](./management-api#versions-and-if-match)). The MCP's settings, overrides, upstream credentials, name and enabled state share one version, so any of these changes invalidates an ETag you read earlier. Try every operation in the [MCP Management API playground](/mcp-gateway-management-playground?tab=settings).

## MCP settings {#settings}

`GET /mcps/{mcp_id}/settings` returns every settings section with defaults filled in, and whether QuilrQL policies are authoritative (`policy_authority.mode`). `PATCH /mcps/{mcp_id}/settings` (scope `settings:write`) changes one or more sections:

| Section | What it controls | Patch behavior |
| --- | --- | --- |
| `tools` | Per-tool settings such as enabled state and confirmation, keyed by tool name. | Merges by key. |
| `dlp` | Data loss prevention actions and enabled risk categories. See [Security guardrails](../protect/security-guardrails). | Merges by key. |
| `token_saving` | Output transforms that reduce tokens sent to the model. See [Token saving](../protect/token-saving). | Merges by key. |
| `access_control` | Which agents, smart groups and users may use this MCP. Deny lists win. See [Server access](../protect/server-access). | Merges by key. |
| `tool_sync` | What happens when the upstream tool list changes: `notify` (record the change for review), `auto` (refresh the tool list) or `off`. | Merges by key. |
| `tool_exposure` | Smart tool lists: list only the most-used tools plus a tool search, or expose a code tool. See [Tool lists](../protect/tool-lists). | Merges by key. |
| `onemcp` | How this MCP takes part in [OneMCP](../get-started/onemcp); `hidden` makes it reachable only at its own endpoint. | Merges by key. |
| `web_search_policy` | Web search policy of the QuilrAI Web Search MCP. See [Web search security](../protect/web-search-security). | Replaces the stored value. |
| `oauth_scopes` | OAuth scopes requested from the provider. See [OAuth permissions](../servers-and-connections/oauth-permissions). | Replaces the stored value; `null` clears it. |
| `send_user_claims_header` | Forward user claims to the upstream server. See [Claims forwarding](../protect/claims-forwarding). | Sets the value. |
| `upstream_session_max_concurrency` | Maximum concurrent upstream sessions (1 to 256). | Sets the value; `null` clears it. |

```bash
curl --request PATCH "$GW/mcpgateway/management/v1/mcps/a1b2c3d4/settings" \
  --header "Authorization: Bearer $KEY" \
  --header 'If-Match: "r4"' \
  --header 'Content-Type: application/json' \
  --data '{"tools": {"delete_file": {"enabled": false}, "write_file": {"enforce_confirmation": true}}}'
```

Unknown fields at any depth are refused with `400` and their paths in `error.fields`. Changes apply immediately to the MCP's own endpoint and to OneMCP.

:::info QuilrQL policies
When QuilrQL policies govern your organization, settings are saved but not enforced, and the response carries an `inactive_under_quilrql` warning. See the [Policy Engine](../../console/govern/policy-engine).
:::

## Per-user and per-group overrides {#overrides}

Overrides change the `tools`, `dlp` and `token_saving` settings for one user (an email in your organization) or one smart group. A user override wins over smart group overrides, which win over the MCP settings.

| Operation | Scope |
| --- | --- |
| `GET /mcps/{mcp_id}/scoped-settings` lists every override. | `read` |
| `PUT /mcps/{mcp_id}/scoped-settings/{scope_type}/{scope_value}` creates or replaces one. `scope_type` is `user` or `smart_group`. `"enabled": false` keeps the override stored but inactive. | `settings:write` |
| `DELETE /mcps/{mcp_id}/scoped-settings/{scope_type}/{scope_value}` removes one; `deleted` is `false` when none existed. | `settings:write` |

## Upstream credentials {#upstream-credentials}

The static credential and the extra headers or query parameters that the gateway sends to the MCP's upstream server. Secrets are write-only: reads return whether a credential is configured, how it is sent, and the names of extras, never their values. Credentials set here are shared by all users of the organization.

| Operation | Behavior |
| --- | --- |
| `GET /mcps/{mcp_id}/upstream-auth` | Credential metadata (scope `read`). |
| `PUT /mcps/{mcp_id}/upstream-auth` | Creates, rotates or changes the credential and extras (scope `credentials:write`). `type` is `bearer`, `header` or `query`. Omitted extras keep the stored ones; `{}` clears them. Not available for OAuth MCPs: connect them with a [connect link](./connections-and-oauth-api#connect-links). |
| `DELETE /mcps/{mcp_id}/upstream-auth` | Removes the credential and, unless `keep_extras=true`, the extras (scope `credentials:write`). Refused with `409 policy_dependency` while the active QuilrQL policy depends on them. |

## Tool reviews {#tool-reviews}

When new upstream tools are held for review, clients do not see them until they are approved. See [Tool change watch](../protect/tool-change-watch).

`GET /mcps/{mcp_id}/tool-reviews` returns the review mode and the tools detected upstream that are held, rejected or already approved. `POST .../tool-reviews/approve` adds the named tools to the tool list; `POST .../tool-reviews/reject` keeps them hidden from clients. Both take `{"tools": [...]}`, need `tool_reviews:write`, and answer `409 tools_not_awaiting_review` when a named tool is not awaiting review.
