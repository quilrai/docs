# CLAUDE.md

Read this before touching anything. This is the QuilrAI documentation site. It is a **Docusaurus 3.9.2** static site that builds to `build/` and auto-deploys to **GitHub Pages at https://docs.quilrai.dev** on every push to `main` (`.github/workflows/deploy.yml`). There is no app, no database, no backend here. It is docs. Treat content as production.

`AGENTS.md` is a symlink to this file. Same rules for every agent.

---

## Hard rules — break these and you break the build or the commit

1. **Every doc page and every category needs an icon, from the allowlist.** No exceptions.
   - `.md`/`.mdx` pages: frontmatter `sidebar_custom_props.icon: <Name>`.
   - `_category_.json`: `customProps.icon: <Name>`.
   - Valid names live in **`src/utils/sidebarIcons.js`** (the `iconMap`). That file is the single source of truth — not the list in `.cursor/rules/docs-icons.mdc`, which drifts.
   - If no existing icon fits: import a new one from `lucide-react` into `src/utils/sidebarIcons.js`, add it to `iconMap`, then use the exact export name. **`lucide-react` is v1.7.0 — brand icons were removed. `Github` and `Slack` DO NOT EXIST.** Verify an icon exists before importing: `node -e "console.log(!!require('lucide-react').Foo)"`.
   - Enforced by `.husky/pre-commit` → `node scripts/check-sidebar-icons.js --staged`. A missing/invalid icon **blocks the commit**. Run `npm run check-icons` to check everything.

2. **Broken internal links fail the build.** `onBrokenLinks: 'throw'` in `docusaurus.config.js`. Always run `npm run build` before you claim done. The build is the link checker.

3. **No em dashes in `docs/**/*.md`.** Use regular `-`. There's a cleanup script: `./replace-em-dashes.sh` (rewrites U+2014 → `-` across all docs). Don't introduce them in the first place.

4. **One sidebar per product, generated from the filesystem.** `sidebars.js` has eight entries (`console`, `llm`, `mcp`, `agents`, `red`, `browser`, `endpoint`, `integ`), each `{type: 'autogenerated', dirName: '<product folder>'}`. You do NOT edit it to add pages. Ordering is `sidebar_position` (page frontmatter) and `position` (`_category_.json`). Sidebar text comes from `sidebar_label`. Links that point into another product (e.g. Console › Settings › "LLM Gateway settings") and link-only groups (Console › Assessments) are injected by `sidebarItemsGenerator` in `docusaurus.config.js` from `crossLinks` / `syntheticCategories` in `src/data/products.js`.

5. **Docs are served at the root, not `/docs`.** `routeBasePath: '/'`. The homepage is `src/pages/index.js` (platform map), not a doc. Each product landing is `docs/<product>/overview.mdx` with `slug: /<product>` rendering `<ProductLanding product="<id>" />`. Internal links between docs are URL-relative (e.g. `./quick-start`, `../protect/security-guardrails`, `../../console/govern/policy-engine`).

6. **Moved pages keep their old URLs.** `src/data/redirects.json` maps every old route to its new one (wired into `plugin-client-redirects`, plus `.md` and `/docs` variants). When you move or delete a page, add an entry (a `#section` target is fine for merged pages). Never redirect a path that still exists. Run `npm run check-redirects` after building.

7. **`llms.txt` is generated, never hand-edited.** `plugins/llms-txt.js` builds `/llms.txt`, `/llms-full.txt`, `/llms/<product>.txt` and `/llms/<product>-full.txt` from the sidebars at build time (dev server serves them too). Entry text = page title + frontmatter `description` (else the first paragraph), so give every page a one-sentence `description`. The "Open in AI" launcher and the per-page "Open in AI" menu point assistants at these files (`src/data/aiProviders.js`). The two console navigation guides for AI agents, `static/llmgateway_guide_for_admin_console.txt` and `static/mcpgateway_guide_for_admin_console.txt`, ARE hand-maintained: update them when those console pages change (linked via `consoleGuide` in `src/data/products.js`).

8. **The Deployment SOP at `/sop/` comes from `quilrai/installdocs`, never from this repo.** `scripts/sync-install-sop.js` clones that repo's `main` and copies `static/sop/` into our `static/sop/` (gitignored) on `prestart` / `prebuild`, so every build ships its latest. Edit the SOP in installdocs; a push there fires `repository_dispatch: install-sop-updated` at `deploy.yml` (needs the `DOCS_DISPATCH_TOKEN` secret in installdocs), and a daily scheduled build catches anything missed. Link to it only through `<InstallSop track="..." />` (embed with step tabs) and `<SopLink track="..." step="..." />` (inline link); never hand-write `/sop/...` URLs. Step keys are the slugged step titles (`installing-using-mdm`), read from the synced folders by `plugins/install-sop.js`; an unknown key fails the build. Offline: an existing copy is kept with a warning (`SKIP_SOP_SYNC=1` skips the pull); with no copy the build fails. Preview SOP edits with `INSTALL_SOP_SOURCE=/path/to/installdocs npm start`. Note `npm run serve` strips `index.html` from URLs, which breaks the SOP's relative CSS locally; `npm start` and GitHub Pages are fine.

## Where everything is

### `docs/` - all content, one folder per product
Each product folder has an `overview.mdx` landing and category subfolders (each with `_category_.json`: label, position, icon, `link: null`). Product metadata (name, tagline, tasks, screenshot, accent) lives in `src/data/products.js`.

| Path | Product | Groups |
|------|---------|--------|
| `docs/console/` | Console (V2) | Mirrors the console menu: `get-started/`, `observe/` (one page per Observe page), `govern/` (Policy Engine, Detection Models, Action requests), `settings-ai-gateway/` (Skills Library; Workflow Agents is its own product), `settings-organization/`, `settings-data/`, `settings-sensors/`, and `legacy-v1/` (collapsed Console V1 guide). |
| `docs/llm-gateway/` | LLM Gateway | `get-started/`, `apps-and-providers/`, `protect/`, `cost-and-traffic/`, `monitor/`, `self-service/`, `api-reference/` (Management API, unified completions, log export), `release-notes/`. |
| `docs/mcp-gateway/` | MCP Gateway | `get-started/`, `servers-and-connections/`, `protect/`, `local-mcp/`, `provider-setup/` (vendors needing an OAuth app), `quilr-provided-mcps/` (QuilrAI-built servers, one page per vendor), `api-reference/`. |
| `docs/workflow-agents/` | Workflow Agents | `get-started/`, `build/` (builder, Library templates, teams), `run-and-share/` (chat and tasks, Manage agent drawer, Self Service), `slack/` (Slack options, Slack as a tool, chat from Slack), `monitor/` (Usage). |
| `docs/red-teaming/` | Red Teaming | `get-started/`, `assessments/` (one page per console tab), `operate/`. |
| `docs/browser-extension/` | Browser Extension | `get-started/`, `deploy/` (Intune, Jamf, GPO), `configure/`, `capabilities/` (clipboard, file indexing, kill switch). |
| `docs/endpoint-agent/` | Endpoint Agent | `get-started/`, `configure/`, `how-it-works/`, `deploy-and-operate/`. |
| `docs/integrations/` | Integrations | `get-started/`, `pull-ai-usage-and-inventory/`, `send-logs-and-alerts/`. |

**Control pages** (`llm-gateway/protect/*`, `llm-gateway/cost-and-traffic/*`, `mcp-gateway/protect/*`) follow one pattern: what it does, turn it on in the app or server settings, settings reference, "Going further with the Policy Engine" (the card it lives on and advanced scenarios), related links. The Policy Engine pages in `console/govern/` cover the engine itself and link out to these.

**Console pages** match console menu items one to one; tabs inside a console page become H2s. Name things exactly as the console UI does.

`docs/mcp-gateway/provider-setup/` is the pattern for "add a provider that needs an OAuth app": `overview.md` explains when you need an OAuth app vs. just a URL; vendor pages walk through creating the app and copying Client ID + Secret. QuilrAI-built servers go in `quilr-provided-mcps/` instead. To add a vendor: drop in a new `.md` (with an icon and `sidebar_position`), add it to the folder's `overview.md` list.

Files or folders starting with `_` are ignored by Docusaurus.

### `src/` — Docusaurus customization (this is a heavily themed site; don't casually rewrite theme files)
- **`src/theme/MDXComponents.js`** — registers components available in **every** `.md`/`.mdx` with **no import needed**:
  - `<StepFlow>` — horizontal step/flow diagram (`steps={[{label, items:[]}]}`; `✓`/`✗` in items get colored).
  - `<ArchitectureDiagram>` — pipeline/box diagram.
  - `<ExpandableTable>` — **overrides the default `table` element**, so every Markdown table is automatically expandable/fullscreen. You usually just write a normal Markdown table.
  - `<InstallSop>`, `<SopLink>` - the Deployment SOP embed and inline step link (rule 8).
  - `<SdkApiKeyTester>`, `<LogExportPlayground>` — interactive playgrounds that call **live `*.quilr.ai` endpoints**. Used in `docs/playground/`.
- `src/theme/` (rest) — swizzled overrides: sidebar items (`DocSidebarItem/*` render the icons), code block copy buttons, doc cards, generated-index page, navbar + mobile sidebar, admonitions, TOC, search bar, layout. Changing these affects every page — be careful.
- `src/components/` — the components above plus `ProductLanding` (product landing pages), `AskAiLauncher` (floating "Open in AI" button on every page: open this page or the product docs in ChatGPT/Claude/etc., copy as markdown), `DocPageCopyDropdown` (the per-page Copy page / Open in AI menu), `SidebarHeader`, `SidebarThemeToggle`.
- **`src/utils/sidebarIcons.js`** — the icon allowlist (see rule 1).
- **`src/data/products.js`** — the eight products: navbar tabs, sidebar header, landing content, accents, cross-links. Add a product here, in `sidebars.js`, and as a `docs/<slug>/` folder.
- `src/data/aiProviders.js` — provider list + prompt builders for the "Open in AI" features.
- `src/themes/prismLight.js`, `prismDark.js` — code-block syntax themes.
- `src/css/custom.css` — global CSS (Tailwind v4 via `@tailwindcss/postcss`, + typography plugin).

### Everything else
- **`plugins/doc-page-markdown.js`** — serves every doc as a raw `.md` file (dev: middleware; prod: written to `build/`). Powers "copy/view as markdown" and the `.md` URLs in `llms.txt`. If a page exists, `<page>.md` and a plain-text twin `<page>.txt` exist (the `.txt` is for AI tools such as ChatGPT that fail on `text/markdown`; prompts link it).
- **`plugins/llms-txt.js`** - generates the llms.txt family (rule 7).
- **`plugins/install-sop.js`** + **`scripts/sync-install-sop.js`** - the Deployment SOP at `/sop/` (rule 8). Component: `src/components/InstallSop` (`<InstallSop>`, `<SopLink>`); `plugins/ai-markdown.js` turns both into plain links in the `.md` / llms output. The SOP pages: `docs/endpoint-agent/deploy-and-operate/installation-sop.mdx`, `docs/browser-extension/deploy/installation-sop.mdx`.
- **`scripts/check-sidebar-icons.js`** — the icon enforcer (rule 1). Runs on pre-commit (`--staged`) and via `npm run check-icons` (all).
- **`static/`** — copied to site root verbatim. `img/` (referenced in docs as `/img/...`), console guides for AI agents (rule 7), `CNAME` (custom domain), `robots.txt`.
- `.cursor/rules/docs-icons.mdc` — Cursor rule restating the icon requirement.
- `.github/workflows/` — `deploy.yml` (build + deploy to GH Pages on push to `main`, on `repository_dispatch: install-sop-updated` from installdocs, daily, and manually), `test-deploy.yml` (PR build check).
- `sidebars.js` (autogenerated — don't edit for content), `docusaurus.config.js`, `package.json`.
- `build/`, `.docusaurus/`, `node_modules/` — generated. Never edit, never commit by hand.

## Commands

```bash
npm start            # local dev server with hot reload
npm run build        # production build — ALSO your link + config validator. Run before done.
npm run serve        # serve the built site locally
npm run check-icons  # validate all sidebar icons (subset of pre-commit)
npm run check-redirects  # after a build: every old URL redirect lands on an existing page and #section
npm run sync-sop     # pull the Deployment SOP from quilrai/installdocs into static/sop/ (also runs before start/build)
./replace-em-dashes.sh   # strip em dashes from docs/**/*.md
```

Node >= 20.

## Writing a page — the checklist
1. Create `docs/<product>/<group>/<page>.md`. A new group folder needs `_category_.json` (label, position, icon, `link: null`).
2. Frontmatter, every page:
   ```yaml
   ---
   sidebar_position: <n>
   sidebar_custom_props:
     icon: <NameFromSidebarIcons>
   ---
   ```
3. Write content. Tables are auto-expandable. Use `<StepFlow>` / `<ArchitectureDiagram>` for flows (no import). Admonitions (`:::tip`, `:::note`, `:::warning`) are themed. Mermaid is enabled. Images go in `static/img/`, referenced as `/img/<file>`.
4. Internal links are relative and have no `.md` extension in the rendered link (e.g. `[OneMCP](../onemcp)`).
5. No em dashes.
6. Add a one-sentence `description` to the frontmatter (it feeds `llms.txt` and the page meta description).
7. `npm run build` — confirm no broken-link or icon errors.

When in doubt, copy the structure of an existing neighboring page. Match the surrounding tone and frontmatter exactly.
