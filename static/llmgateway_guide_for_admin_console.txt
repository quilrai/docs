QUILR ADMIN CONSOLE (v2) - LLM GATEWAY NAVIGATION GUIDE FOR BROWSING AGENTS
Last verified: 2026-10-07 against web.quilr.ai
Labels below are the exact on-screen text. ">" means "then click".

WHERE
- Sidebar: Settings > AI Gateway > LLM Gateway        URL /settings/llm-gateway
- Page tabs: Applications (default) | Management API   /settings/llm-gateway/management-api
- Sibling: Settings > AI Gateway > Models              /settings/models (opens /settings/models/models)
- Not visible? The user lacks LLM Gateway access; a warning banner means management is disabled for the organization.

PAGE LAYOUT (Applications tab, top to bottom)
- Header buttons: Overall analytics | Provider health | Self-service usage | Audit log |
  Provider configuration | Create App (primary) | "..." (More LLM Gateway actions) > Copy all-apps log key
- Metric strip: REQUESTS (People calling, Models in use, Success; click = analytics) |
  APPLICATIONS (click Active/Inactive/Expired = filter) |
  NEEDS ATTENTION (Not routable / No guardrails / Expiring in 30d = filter) |
  STOPPED BY GUARDRAILS (Redacted, Failed requests, p95 latency)
- Warning banner if an app has every provider disabled: Configure <app> or Review all
- "Providers & models" strip: View in Models | Provider configuration; one tile per platform
  provider (label, provider type, model count, "Used by N apps"; click = Provider configuration drawer)
- "Configured Apps": docs link chip, search box ("App, key, provider, model, creator, or tag"),
  Filter (Attention, Status, Provider, Model, Tag, Creator), period button (Last 7 days),
  sort button (default "Creation date & time"), then one card per app
- App card:
  header: name, key status, Tag button, Manage keys, Integration docs
  "API Keys: N active / N expired / N revoked" row (click = API Keys section)
  provider/model chips (click = provider settings), P95 latency, errors
  capability chips Identity aware / Prompt store / Token saving / Guardian agent (Yes/No; click = that section)
  Inspect row: Logs | Usage & Cost | Provider Status | Copy logs key | Export API docs
  Configure row: Providers | Guardrails | Guardian | Token Saving | Routing | Self-Service | Audit Log | Prompts
  footer: Created by, Created at
- Every Inspect/Configure button opens the "LLM Gateway workspace" drawer.

WORKSPACE DRAWER ("LLM Gateway workspace")
- Application picker ("All applications" = every app); scope tiles APPLICATIONS IN SCOPE / PROVIDERS / NEEDS ATTENTION
- With one app: summary strip Providers | Models | Protections | Quilr keys, plus a Smart Assist panel
- Tabs: Analytics | Activity | Usage | Health | Settings | Audit
- Activity sub-tabs: Requests | Interactions | Findings (filters Model, Provider, Outcome; period)
- Settings tab needs exactly one app; section list on left, form on right, Discard changes / Save settings at bottom
- Settings section groups and labels:
  PROVIDERS & ROUTING: LLM Providers, Routing
  PROTECTION: Security Guardrails, Guardian Agent, Custom Detections, Rate and Token Limits
  OPTIMIZATION & POLICY: Token Saving, Self-Service, Alerts
  IDENTITY & CONTENT: Identity Aware, Prompt Store
  OPERATIONS: API Keys, API Integration, Audit Log
- Sections governed by the Policy Engine carry a "Controlled by Policy Engine" tag in the list.

TASK -> WHERE
- Create an app -> LLM Gateway > Create App ("STEP 1 OF 2 - APPLICATION AND PROVIDERS") > Application name*,
  optional Application URL, optional "Key settings" (Quilr key name*, Initial key expiry; blank = never)
  > "Where should this app get its models?" pick Platform providers (Recommended) or App-only credentials
  > tick providers (first ticked = primary) > Create app > step 2 "Integration": copy Quilr key,
  Log export key, All-apps log key > Done. "Smart Assist" in the dialog header answers setup questions.
- Add/edit a shared (platform) provider -> Provider configuration (drawer: Search providers, View in Models)
  > Add your own models. Steps Connect > Models > Pricing > Review & save; "Add provider" adds another
  to the same batch. Provider types: OpenAI, Anthropic, Azure, Amazon Bedrock, Google, DeepSeek, Sarvam,
  Cohere / Jina / Voyage (rerank only), Oracle OCI, Custom endpoint. OpenAI asks "Which API does the
  gateway talk to?" (Chat completions | Responses | Assistants | Realtime). Same flow: Models > Add your own models
- Change an app's providers/models/fallbacks -> app card > Configure > Providers (LLM Providers section)
- Set guardrails (PII, secrets, prompt injection, hallucination, source IPs) -> Configure > Guardrails
  (Action mix, Default action, DATA RISKS / adversarial categories; "Copy from another app")
- Guardian Agent (coding/task adherence) -> Configure > Guardian
- Custom detections -> workspace Settings > Custom Detections (detection models: sidebar Detection Models)
- Set rate limits / token budgets / concurrency -> workspace Settings > Rate and Token Limits
- Token saving (compression/caching) -> Configure > Token Saving
- Routing (weighted, token-based, custom) -> Configure > Routing
- Failure-rate alerts (email/webhook) -> workspace Settings > Alerts
- Identity / JWT / conversation ID enforcement -> workspace Settings > Identity Aware
- Prompt Store (approved prompts + enforcement) -> Configure > Prompts
- Self-service for developers -> Configure > Self-Service > Self-service Enabled switch, then Capabilities grid
  (per capability: Allow all users / Allow emails / Allow smart groups / Deny emails / Deny smart groups) > Save settings
- Approve self-service change requests -> Configure > Audit Log > Change requests
- Who uses self-service -> header Self-service usage
- Add / revoke / change the expiry of a Quilr key -> card Manage keys (API Keys section) > "Add a Quilr key":
  Quilr key name*, Expiry > Add key; per key in Keys list: Edit expiry / Revoke
- Get integration snippet / base URL / key -> card Integration docs (API Integration section: pick Quilr key > Copy;
  Log export key > Copy)
- Roll back an app's configuration -> Configure > Audit Log > Configuration versions > Roll back
- Configuration audit across all apps -> header Audit log
- Request logs for an app -> card Logs (Activity > Requests); conversations: Interactions; detections: Findings
- Cost / tokens for an app -> card Usage & Cost
- Provider latency / errors -> card Provider Status, or header Provider health (all apps)
- Estate-wide analytics -> header Overall analytics
- Tag apps -> card Tag button; filter by Tag in Filter
- Log export key -> card Copy logs key; all apps: header "..." > Copy all-apps log key
- Management API keys -> Management API tab > "Allow management keys for this organization" switch
  (off = every key suspended), then "Issue a management key": Key name*, Expiry, Scopes (Read, Configure apps,
  Manage providers, Issue app keys, Reveal app keys) > Issue key. Table: Name, Scopes, Status, Created,
  Expires, Last used, Actions. The key value is shown once.
- Quilr-provided models / model API keys -> Settings > Models: tabs Models | API keys | Usage | Playground
  (/settings/models/models, /settings/models/api-keys). Models tab sources: "QuilrAI provided models" |
  "Your models"; Search models, Sort by price. API keys > Create API key (shown once).
- Govern all apps with policies -> sidebar Policy Engine > LLM Gateway tab (/policy/engine/llm-gateway)
- Costs across gateway -> sidebar Costs & Savings: Overview | Attribution | Savings | Habits | Providers
- Findings across sources -> sidebar Findings & Interactions (LLM traffic shows source "LLM Gateway")
- App as an asset -> sidebar Inventory > open the app: Analytics | Requests | Usage & cost | Settings
- Custom charts -> sidebar Dashboards
- Log retention / exports -> Settings > Data Settings > Data Retention | Export Center

POLICY ENGINE (LLM) - /policy/engine/llm-gateway
- Surface tabs: Browser Extension | LLM Gateway | MCP Gateway | Endpoint Agent
- Header when on: ENGINE ON, Revision N, "Gateway controls", "N of 12 active", History, Docs, Filter
- "What applies to one request" > Describe a request (previews the winning value per control)
- 12 cards (each Configure + Docs): Data & Adversarial Risks, Guardian Agent, Hallucination Protection,
  Gateway Access, Identity & Network Trust, Tool Controls, Allowed Models, Routing Groups & Fallbacks,
  Budgets & Usage Limits, Rate, Token & Timeout Limits, Token Savings, Prompt Store and Enforcement.
  Below them: "Advanced policies" (policies the cards cannot represent; Advanced workspace).
- Edits go to one shared draft > Review changes > Publish revision.
- History: /policy/engine/llm-gateway/history. Simulate: /policy/engine/llm-gateway/simulate
- First time (engine off): "Enable new Policy Engine" > Review conversion > tick both checkboxes in
  "Confirm your review" > Continue to confirmation > confirm (not re-verified: engine already on)

DEEP LINKS (query parameters on /settings/llm-gateway)
- ?create=1                         Create App dialog
- ?providers=manage | add           Provider configuration drawer (add opens Add your own models)
- ?self_service_usage=1             Self-service usage drawer
- ?audit=global                     workspace on Audit tab, all apps
- ?workspace=analytics|activity|usage|health|settings|audit   opens workspace on that tab
- &app=<appId>  or  &apps=<id1,id2> scope (max 24); no app = all apps
- &section=<id> (with workspace=settings): providers, security, guardian, detections, limits,
  token-saving, routing, self-service, alerts, identity, prompts, audit, api-keys, integration
- &activity=interactions|findings   Activity sub-tab (omit = Requests)
- &period=24h|3d|7d|30d|90d|180d|365d (default 7d), or &from=..&to=..
- Register filters (repeatable): llm_status=active|inactive|expired,
  llm_attention=not_routable|unprotected|expiring_soon, llm_provider, llm_model, llm_tag, llm_creator
- Activity drill filters: llm_outcome, llm_model, llm_provider, llm_user
- &interaction=<id> opens a conversation detail drawer
- Example: /settings/llm-gateway?app=<id>&workspace=settings&section=limits
- Models: /settings/models/models?action=add-models ; ?source=quilr|yours ; ?q=<search>
- Policy card anchor: /policy/engine/llm-gateway#policy-surface-<id>; ids: data-risks, guardian,
  hallucination, gateway-access, identity-network, tool-controls, allowed-models,
  routing-groups-fallbacks, budgets, limits, token-saving, prompt-store

CONFIGURATION NOTES
- Policy Engine on (tenant-wide): Security Guardrails, Guardian Agent, Rate and Token Limits, Token Saving,
  Routing follow published policies; per-app values are not enforced. The section shows
  "Policy Engine active - Revision N" and "Controlled by Policy Engine. Live requests follow the published
  ... policies." > View policies (edit in Policy Engine) or Edit anyway > dialog "Edit legacy settings?"
  > Cancel | Edit legacy settings (saved values apply only if the Policy Engine is turned off).
- Partly governed: Custom Detections (on/off, Applies to, Action), Identity Aware (Enforce identity /
  Enforce conversation ID switches), Prompt Store (Enforcement). Definitions, identity sources, prompts stay live here.
- Not governed: LLM Providers, Self-Service, Alerts, API Keys, API Integration, Audit Log.
- Settings save only on "Save settings"; Discard changes reverts. Prompts and custom detection
  definitions save immediately.
- Radio cards (provider source): click the visible card label text ("Platform providers" /
  "App-only credentials"), not a hidden input. This choice can't be changed after the app is created.
- Create App is 2 steps (Application and providers, then Integration); keys are shown once, copy them.
- Settings tab with several apps selected shows "Choose one application to configure"; pick one app.
- No platform providers yet? In Create App use Add a platform provider, or App-only credentials.
- An app with every provider disabled is "Not routable": it accepts keys but routes nothing.
- Header buttons are disabled when management is unavailable; missing buttons mean missing permission.
- Docs may say "Global providers"; the UI says Platform providers. There is no Red Team button on cards.
- llm_provider / llm_model are shared by register filters and the Activity drill; clear them when switching.
