QUILR ADMIN CONSOLE (v2) - LLM GATEWAY NAVIGATION GUIDE FOR BROWSING AGENTS
Updated on 3 November 2026.
Attachment controls and image-risk labels checked against the current console: 2026-11-02.
Labels below are the exact on-screen text. ">" means "then click".

WHERE
- Sidebar: Settings > AI Gateway > LLM Gateway        URL /settings/llm-gateway
- Page tabs: Applications (default) | Management API   /settings/llm-gateway/management-api
- Sibling: Settings > AI Gateway > Models              /settings/models (opens /settings/models/models)
- Not visible? The user lacks LLM Gateway access; a warning banner means management is disabled for the organization.

PAGE LAYOUT (Applications tab, top to bottom)
- Header buttons: Overall analytics | Provider health | Self-service usage | Audit log |
  Provider configuration | Remote Connectors | Create App (primary) | "..." (More LLM Gateway actions) > Copy all-apps log key
- Metric strip: REQUESTS (People calling, Models in use, Success; click = analytics) |
  APPLICATIONS (click Active/Inactive/Expired = filter) |
  NEEDS ATTENTION (Not routable / No guardrails / Expiring in 30d = filter) |
  STOPPED BY GUARDRAILS (Redacted, Failed requests, p95 latency)
- Warning banner if an app has every provider disabled: Configure <app> or Review all
- "Providers & models" strip: View in Models | Provider configuration; one tile per platform
  provider (label, provider type, model count, "Used by N apps"; click = Provider configuration drawer)
- "Configured Apps": docs link chip, search box ("App, key, provider, model, creator, or tag"),
  Filter (Attention, Status, Provider, Model, Tag, Creator), period button (Last 7 days),
  sort button (default "Creation date & time"), then one card per app
- App card:
  header: name, key status, Tag button, Manage keys, Integration docs
  "API Keys: N active / N expired / N revoked" row (click = API Keys section)
  provider/model chips (click = provider settings), P95 latency, errors
  capability chips Identity aware / Prompt store / Token saving / Guardian agent (Yes/No; click = that section)
  Inspect row: Logs | Usage & Cost | Provider Status | Copy logs key | Export API docs
  Configure row: Providers | Guardrails | Guardian | Token Saving | Routing | Self-Service | Audit Log | Prompts
  footer: Created by, Created at
- Logs and Configure actions open operational drawers. Overall analytics and app Analytics links open full-page Insights.

FULL-PAGE INSIGHTS
- Overall analytics opens LLM Gateway Insights, separate from operational Activity/Settings drawers.
- Sections: Overview | Agents & tools | Performance & errors | Security | Attachments | Users.
- Routes under /settings/llm-gateway/insights/: overview, agents, performance, security, attachments, users.
- Period: 24 hours | 3 days | 7 days | 14 days | 30 days; compared with the previous period; All apps picker.
- Model requests / Guardrail checks appears where supported, not identically on every section.
- Overview: Worth a look, app behavior, prompt caching, changes, answer endings, models/routing,
  callers, estimated spend, failed requests, All apps. Explore opens related evidence.
- Agents & tools: All agents | Tools & parameters; Coding agents may be unavailable.
  An agent configuration, an app, and a run are different units. Cost and token figures are estimates.
- Performance & errors: Where the time goes, failures, streaming, rate limiting, output limits,
  served model versions, reasoning, providers and deployments.
- Security: scan completeness, results, findings, actions, app coverage, networks.
  Unavailable scan completeness is not zero coverage.
- Attachments: file counts/bytes, OCR, scan outcomes, data found, image labels, skipped files, apps.
- Users: people/Smart groups, requests/cost/data/outcomes, identity coverage, people-agent-tool flow.
- Open an app card's Logs for request-level Activity; Insights does not have an Activity or Settings tab.

WORKSPACE DRAWER ("LLM Gateway workspace")
- Application picker ("All applications" = every app); scope tiles APPLICATIONS IN SCOPE / PROVIDERS / NEEDS ATTENTION
- With one app: summary strip Providers | Models | Protections | Quilr keys, plus a Smart Assist panel
- Tabs: Analytics | Activity | Usage | Health | Settings | Audit
- Activity sub-tabs: Requests | Interactions | Findings (filters Model, Provider, Outcome; period)
- Settings tab needs exactly one app; section list on left, form on right, Discard changes / Save settings at bottom
- Settings section groups and labels:
  PROVIDERS & ROUTING: LLM Providers, Routing
  PROTECTION: Security Guardrails, Guardian Agent, Custom Detections, Attachments, Rate and Token Limits
  OPTIMIZATION & POLICY: Token Saving, Self-Service, Alerts
  IDENTITY & CONTENT: Identity Aware, Prompt Store
  OPERATIONS: API Keys, API Integration, Audit Log
- Sections governed by the Policy Engine carry a "Controlled by Policy Engine" tag in the list.

TASK -> WHERE
- Create an app -> LLM Gateway > Create App ("STEP 1 OF 2 - APPLICATION AND PROVIDERS") > Application name*,
  optional Application URL, optional "Key settings" (Quilr key name*, Initial key expiry; blank = never)
  > "Where should this app get its models?" pick Platform providers (Recommended) or App-only credentials
  > tick providers (first ticked = primary) > Create app > step 2 "Integration": copy Quilr key,
  Log export key, All-apps log key > Done. "Smart Assist" in the dialog header answers setup questions.
- Add/edit a shared (platform) provider -> Provider configuration (drawer: Search providers, View in Models)
  > Add your own models. Steps Connect > Models > Pricing > Review & save; "Add provider" adds another
  to the same batch. "Search provider types" filters tiles by vendor or API. Provider types: OpenAI, Anthropic, Azure,
  Amazon Bedrock, Google, DeepSeek, Mistral AI, xAI (Chat completions | Responses), Sarvam,
  Cohere / Jina / Voyage (rerank only), Oracle OCI, Custom endpoint. OpenAI asks "Which API does the
  gateway talk to?" (Chat completions | Responses | Assistants | Realtime). Same flow: Models > Add your own models
- Change an app's providers/models/fallbacks -> app card > Configure > Providers (LLM Providers section)
- Connect a private model endpoint -> LLM Gateway > Remote Connectors > create a connector and copy its
  qrc_... token (shown once). Run the shared quilr-connector binary or container in the private network.
  In Provider configuration, set the provider's private Base URL and Connection route > Via Remote Connector,
  then choose the connected connector. Binary, Docker and Kubernetes examples are in the remote connector docs.
- Set guardrails (PII, secrets, prompt injection, hallucination, source IPs) -> Configure > Guardrails
  (Action mix, Default action, DATA RISKS / adversarial categories; "Copy from another app")
- Check uploaded files -> workspace Settings > Attachments > Scan attachments (off by default).
  Allowed files and limits: per-file-kind Allow | Strip | Block; Max file size (MB), Max attachments per
  request (MB), Max new files per request, Max PDF pages; limit action Monitor | Strip | Block.
  Scanning: Extract document text, unreadable-file action, macro-enabled-document action.
  Images and OCR: Read text in images (Off | Images and pages without text | Every page), OCR scripts
  (Every script | Only these), Classify images. Save settings applies app changes when not governed.
- Detect payment-card, ID-document or other image types -> Security Guardrails > Attachments > Image Risks;
  enable the required Image types and choose Monitor | Strip | Block. Scan attachments and Classify images
  must also be on. Image Risks is off by default. Redaction removes the complete attachment.
- Review file scans -> LLM Gateway > Insights > Attachments (/settings/llm-gateway/insights/attachments):
  File kinds, Detected file types, Scan outcomes, Data found in attachment text, Image labels,
  Why attachments were skipped, Apps. Choose a chart or app to review related requests.
- Guardian Agent (coding/task adherence) -> Configure > Guardian
- Custom detections -> workspace Settings > Custom Detections (detection models: sidebar Detection Models)
- Set rate limits / token budgets / concurrency -> workspace Settings > Rate and Token Limits
- Token saving (compression/caching) -> Configure > Token Saving
- Routing (weighted, token-based, custom) -> Configure > Routing
- Failure-rate alerts (email/webhook) -> workspace Settings > Alerts
- Identity / JWT / conversation ID enforcement -> workspace Settings > Identity Aware
- Prompt Store (approved prompts + Universal system prompt + enforcement) -> Configure > Prompts
- One prompt added to every request of an app -> Configure > Prompts > "Universal system prompt" card:
  type the Prompt, turn on "Apply to every request" > Save settings (no Prompt ID; added before the request's
  own system prompt). With the Policy Engine on, set it on the Policy Engine "Prompt Store & Enforcement"
  card instead (see POLICY ENGINE)
- Self-service for developers -> Configure > Self-Service > Self-service Enabled switch, then Capabilities grid
  (per capability: Allow all users / Allow emails / Allow smart groups / Deny emails / Deny smart groups) > Save settings
- Approve self-service change requests -> Configure > Audit Log > Change requests
- Who uses self-service -> header Self-service usage
- Add / revoke / change the expiry of a Quilr key -> card Manage keys (API Keys section) > "Add a Quilr key":
  Quilr key name*, Expiry > Add key; per key in Keys list: Edit expiry / Revoke
- Get integration snippet / base URL / key -> card Integration docs (API Integration section: pick Quilr key > Copy;
  Log export key > Copy)
- Roll back an app's configuration -> Configure > Audit Log > Configuration versions > Roll back
- Configuration audit across all apps -> header Audit log
- Request logs for an app -> card Logs (Activity > Requests); conversations: Interactions; detections: Findings
- Cost / tokens for an app -> card Usage & Cost
- Provider latency / errors -> card Provider Status, or header Provider health (all apps)
- Estate-wide analytics -> header Overall analytics
- Tag apps -> card Tag button; filter by Tag in Filter
- Log export key -> card Copy logs key; all apps: header "..." > Copy all-apps log key
- Management API keys -> Management API tab > "Allow management keys for this organization" switch
  (off = every key suspended), then "Issue a management key": Key name*, Expiry, Scopes (Read, Configure apps,
  Manage providers, Issue app keys, Reveal app keys, Read budgets, Manage budget grants, Configure budgets,
  Read routing, Manage routing, Manage routing constraints, Read limits, Manage limits, Grant limit raises,
  Read incidents, Manage incidents, Manage hooks, Manage personal keys)
  > Issue key. Table: Name, Scopes, Status, Created, Expires, Last used, Actions. The key value is shown once.
  Try the key from the browser: https://docs.quilrai.dev/llm-gateway-management-playground
- External hooks (your own API called on gateway traffic) -> Management API tab > "Configured hooks": read-only
  list of each hook's stage, mode, scope and destination. Create and change hooks only through the Management
  API (scope hooks:write): https://docs.quilrai.dev/llm-gateway/api-reference/hooks-api
- Quilr-provided models / model API keys -> Settings > Models: tabs Models | API keys | Usage | Playground
  (/settings/models/models, /settings/models/api-keys). Models tab sources: "QuilrAI provided models" |
  "Your models"; Search models, Sort by price. API keys > Create API key (shown once).
- Govern all apps with policies -> sidebar Policy Engine > LLM Gateway tab (/policy/engine/llm-gateway)
- Hide models from GET /v1/models and Get available models (still callable by name) -> Policy Engine >
  LLM Gateway > Model Visibility card (see POLICY ENGINE)
- Costs across gateway -> sidebar Costs & Savings: Overview | Attribution | Savings | Habits | Providers
- Findings across sources -> sidebar Findings & Interactions (LLM traffic shows source "LLM Gateway")
- App as an asset -> sidebar Inventory > open the app: Analytics | Requests | Usage & cost | Settings
- Custom charts -> sidebar Dashboards
- Log retention -> Settings > Data management > Data Retention (/settings/data-management/data-retention):
  LLM Gateway is the only configurable source; support for other sources is releasing soon. Default sets
  prompt, response, log, detected-value, identity and diagnostics retention. Add scoped cards for models,
  apps, users/smart groups or detected data; the shortest matching duration wins, including Default.
  Zero data retention uses Never store for prompts/responses/detected values/identity; basic usage and
  cost metadata remains. Check Default after applying a template: people cards can require identity retention.
  Review impact > Apply and confirm; Save draft does not apply changes.
- Exports -> Settings > Data management > Export Center

POLICY ENGINE (LLM)
- Workspace: /policy/engine/llm-gateway. Selector: LLM Gateway | MCP Gateway | Endpoint Agent | Cloud & SaaS.
- Header: POLICY ENGINE ON, Updated time, More. Sections: Controls | Policies | Groups | Test | History.
- Groups (/policy/engine/llm-gateway/groups): Rank column = editable number (API field priority; lower wins, ties by
  name, turned-off groups govern no one); Strength column = resulting position, #1 strongest (API field rank).
  Edit rank / Reset to synced rank, New virtual group, Edit group, Delete group.
  Saving a rank opens "Change group rank?" listing people who change governing group, budgets they switch
  and only the rank ties the change creates.
- Controls groups and areas:
  Who can use AI?: Gateway Access, Identity & Network Trust, Allowed Models, Model Visibility,
  Prompt Store & Enforcement.
  What should be checked?: Data & Adversarial Risks, Guardian Agent, Tool Controls, Attachments.
  Which model and limits?: Routing Groups & Fallbacks, Budgets & Usage Limits, Token Savings.
  What may return?: Hallucination Protection, Error Messages.
- Open an area > read What happens today, section defaults and How rules combine > start from a recipe
  or blank rule > Applies to > outcome > Reads as > Save to draft > Review & publish.
- Most panels: Controls | Activity. Prompt Store & Enforcement also has Prompt Store.
- Gateway Access: Who can send requests, Prompt text rules. Highest priority wins, Deny wins ties.
- Allowed Models: Search rules; allowed lists combine; a matching rejected list wins regardless of priority.
- Model Visibility: Model listing, Show only, Hide, Undated aliases, Who still sees hidden models.
- Identity & Network Trust: Require identity, Require conversation ID, Allowed source IPs, Identity capture.
  Identity sources remain per app; capture overrides and defaults are shown per setting.
- Data & Adversarial Risks: Language Blocking, Detection rules, Tag matching traffic.
  Do not assume a lower-priority Block defeats every higher-priority action; read the section's combination rule.
- Guardian Agent: Guardian, Coding helpers, Task adherence, Tag findings.
- Hallucination Protection: Protection, Tag findings.
- Attachments: Scanning, File types, Size and count limits, Files that can't be scanned, Text in images (OCR).
  Text/image data types and actions belong in Data & Adversarial Risks.
- Routing Groups & Fallbacks: Routes | Failover defaults | Activity; Search routes, models or groups;
  filter by All, Limits, Split, Try in order, Content, Watch only.
- Budgets & Usage Limits: Budgets & rate limits | Usage | Grants | Request guards | Alerts & response |
  Exemptions | Model prices. Search limits; there is no separate Rate, Token & Timeout Limits area.
  Per-group budgets: "When someone is in several of these groups" > Their strongest group's budget applies (by rank)
  (default for new) | Every group's budget applies (strictest wins). Sets created via the API show "Managed by API".
- Token Savings: Smart JSON compression, HTML to text, Markdown to text, Text compression,
  Minify JSON tool outputs, Clean up tool output, Remove encoded content, Response cache.
- Error Messages: ordered matching messages/help links; status/error codes unchanged.
  Errors before app identification and limit refusals using a Limit response are excluded.
- Applies to supports Exclude something and More targeting options. A short app shortcut list is not the
  full catalog: Search Application values > Find application. Read wildcard and priority explanations.
- Policies: Search policies, Filters, policy details, Add rule, Edit technical source.
- Test: Try a situation | Replay activity. Check which rules are selected for testing.
  Try a situation: Person, Application, AI model, Request type, More details, Add detail,
  Sensitive data types (optional), Test multiple situations > Run test.
  Replay activity: Time range, Advanced replay options > Run check. Neither changes live traffic.
- History: Version list with actor/reason; compare Previous version or Live version; change summary;
  Technical details, Technical source and Source diff. Restoring preserves history as a new version.
- Panel links use ?tile=<id>&tab=controls or activity. Observed ids: gateway-access, identity-network,
  allowed-models, model-visibility, prompt-store, data-risks, guardian, tool-controls, attachments,
  routing-groups-fallbacks, budgets, token-saving, hallucination, error-messages.

DEEP LINKS (query parameters on /settings/llm-gateway)
- ?create=1                         Create App dialog
- ?providers=manage | add           Provider configuration drawer (add opens Add your own models)
- ?self_service_usage=1             Self-service usage drawer
- ?audit=global                     workspace on Audit tab, all apps
- ?workspace=analytics|activity|usage|health|settings|audit   opens workspace on that tab
- &app=<appId>  or  &apps=<id1,id2> scope (max 24); no app = all apps
- &section=<id> (with workspace=settings): providers, security, guardian, detections, limits,
  token-saving, routing, self-service, alerts, identity, prompts, audit, api-keys, integration
- &activity=interactions|findings   Activity sub-tab (omit = Requests)
- &period=24h|3d|7d|30d|90d|180d|365d (default 7d), or &from=..&to=..
- Register filters (repeatable): llm_status=active|inactive|expired,
  llm_attention=not_routable|unprotected|expiring_soon, llm_provider, llm_model, llm_tag, llm_creator
- Activity drill filters: llm_outcome, llm_model, llm_provider, llm_user
- &interaction=<id> opens a conversation detail drawer
- Example: /settings/llm-gateway?app=<id>&workspace=settings&section=limits
- Models: /settings/models/models?action=add-models ; ?source=quilr|yours ; ?q=<search>

CONFIGURATION NOTES
- Policy Engine on (tenant-wide): Security Guardrails, Guardian Agent, Attachments, Rate and Token Limits, Token Saving,
  Routing follow published policies; per-app values are not enforced. The section shows
  "Policy Engine active - Revision N" and "Controlled by Policy Engine. Live requests follow the published
  ... policies." > View policies (edit in Policy Engine) or Edit anyway > dialog "Edit legacy settings?"
  > Cancel | Edit legacy settings (saved values apply only if the Policy Engine is turned off).
- Partly governed: Custom Detections (on/off, Applies to, Action), Identity Aware (Enforce identity /
  Enforce conversation ID switches), Prompt Store (Enforcement and the Universal system prompt card).
  Definitions, identity sources and prompts stay live here.
- Not governed: LLM Providers, Self-Service, Alerts, API Keys, API Integration, Audit Log.
- Settings save only on "Save settings"; Discard changes reverts. Prompts and custom detection
  definitions save immediately. The Universal system prompt and its "Apply to every request" switch save
  with "Save settings".
- Radio cards (provider source): click the visible card label text ("Platform providers" /
  "App-only credentials"), not a hidden input. This choice can't be changed after the app is created.
- Create App is 2 steps (Application and providers, then Integration); keys are shown once, copy them.
- Settings tab with several apps selected shows "Choose one application to configure"; pick one app.
- No platform providers yet? In Create App use Add a platform provider, or App-only credentials.
- An app with every provider disabled is "Not routable": it accepts keys but routes nothing.
- Header buttons are disabled when management is unavailable; missing buttons mean missing permission.
- Docs may say "Global providers"; the UI says Platform providers. There is no Red Team button on cards.
- llm_provider / llm_model are shared by register filters and the Activity drill; clear them when switching.
