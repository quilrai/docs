QUILR ADMIN CONSOLE (v2): MCP GATEWAY GUIDE FOR BROWSING AGENTS
Updated on 14 November 2026.
Labels below are the exact on-screen text. ">" means "then click".

WHERE
- Page: sidebar Settings > AI Gateway > MCP Gateway  (URL /settings/mcp-gateway)
- Page tabs: Servers (default) | Management API   /settings/mcp-gateway/management-api
- Command palette: type "MCP Gateway", "Add MCP", "MCP library", "MCP Gateway health"
- Siblings in AI Gateway group: Workflow Agents, LLM Gateway, MCP Gateway, Models, Skills Library

PAGE LAYOUT (top to bottom)
- Header buttons: Overall analytics | OneMCP endpoint | Remote Connectors | Library (badge = pending user install requests) |
  Tool updates | Allowed Agents | Add MCP server | "..." (More MCP Gateway actions) > Connections | ZIA integration
- Summary tiles (rows are clickable filters/shortcuts):
  TOOL CALLS: People calling, Tools called, Success, "% of them came through OneMCP" -> opens analytics
  ESTATE: Serving / Awaiting / No tools -> filters server list by state; "N enabled - N disabled"
  TOOLS REACHABLE: Scoped rules, OAuth servers (filters auth=oauth), Library queue (opens Library)
  STOPPED BY GUARDRAILS: Guardrail flags, Failed calls, p95 latency
- Banners: "N OAuth servers need an administrator connection..." -> Review all (or "Connect <name>" if only one)
           "N quick fixes could prevent failed tool calls..." -> Review fixes
- Links row "ELSEWHERE": Inventory & analytics, User dashboard (external), Documentation
- "Configured servers": note "Users can login at mcpgateway.quilr.ai"; help buttons "How to Use as an Admin"
  and "How Do Users Use MCP Gateway"; tabs All / Local / Remote / API with counts (API tab only when an API MCP
  exists), "Search servers", Filter (State, Auth, Source, Runtime)
- Server card: name, tags System / Library / Local package / Remote Connector / alias count, slug, description; QUILR GATEWAY
  endpoint, UPSTREAM (or API base URL), p95/failures, status (SERVING etc.), transport, auth
  Chips: Tools, Guardrails, Scoped rules, Token saving (each opens that Configure section), Show tools,
  Uninstall, enable toggle; usage stats (calls, users, tokens saved, top tools)
  Rows: Inspect (Logs = activity, Open in Inventory) | Configure (General, Guardrails, Token Saving, Tools,
  Group & User Rules; API on API MCPs)
  Awaiting servers show a "Connect OAuth" button

FULL-PAGE INSIGHTS
- Overall analytics opens MCP Gateway Insights, separate from operational Activity/Settings drawers.
- Sections: Overview | Usage | Data & security | Reliability | Servers & tools.
- Routes under /settings/mcp-gateway/insights/: overview, usage, security, reliability, servers.
- Period: 3 days | 7 days | 30 days | 90 days; compared with previous period; All servers and All AI clients.
- Overview: calls, people, failures, detections, topics, what AI touched, Needs attention, top servers/users.
  Topics show classification coverage and activity grouped into six-hour UTC windows.
- Usage: active/new/returning people, repeat usage, adoption by server, client/server relationships, people search.
- Data & security: read/write/execute classifications, resources named, access map, AI changes,
  flagged requests/responses, prompt-injection sources, affected people.
- Reliability: failure ownership/reasons, affected tools/servers, latency, input mismatch evidence.
- Servers & tools: health/access filters, Servers/Tools toggle, tool-list savings, idle definition overhead,
  tokens returned to AI; select a tool for Overview | Output size | Data protection.
- Tool-list savings and tool-response compression savings measure different things.
- Insights has no Activity, Connections or Settings tab; use server Logs/Configure or the gateway's
  operational workspace/Connections entry point for those tasks.

WORKSPACE DRAWER ("MCP Gateway workspace")
- Server picker ("All servers"); tiles SERVERS IN SCOPE / SERVING TOOLS / NOT SERVING
- Tabs: Analytics | Activity | Connections | Health | Settings
- Analytics: Summary, Traffic, Guardrails, People & tools, Servers, Agents & clients, Workflow graph, Topics
- Activity sub-tabs: Tool calls | Interactions | Findings
- Settings (one server): header strip Tools / Calls / Scoped rules / Endpoint; section list General, Tools,
  Guardrails, Token saving, Tool list (remote servers), Input aliases, Group & User Rules, plus conditional API,
  Permissions, API tokens;
  footer Discard changes | Save settings; Smart Assist panel at the bottom

TASK -> WHERE
- Management API keys -> Management API tab > "Allow management keys for this organization" switch
  (off = every key suspended), then "Issue a management key": Key name*, Expiry (leave blank for no expiry),
  Scopes (Read, Manage MCPs, Change settings, Set credentials, Review tools) > Issue key. Dialog
  "Management key created" shows the key once (Copy key > Done). Table "Management keys": Name, Scopes, Status,
  Fingerprint, Created, Expires, Last used, Actions (edit: Key name, Expiry, Never expires > Save changes;
  revoke: "Revoke <name>?" > Revoke key). API docs: https://docs.quilrai.dev/mcp-gateway/api-reference/management-api
  Try the key from the browser: https://docs.quilrai.dev/mcp-gateway-management-playground
- Add remote MCP -> Add MCP server (dialog "Add MCP") > "Remote server" > Name, Slug (optional), Transport URL,
  "Connection route": Public internet / Via Remote Connector: <name>, Description > "How the gateway signs in":
  Auto-detect (recommended) / OAuth passthrough / Upstream API key > optional "Custom headers & query parameters"
  > Probe and continue. Steps: Connection > Credentials > Registered. If the probe finds OAuth, the "Connect with OAuth"
  step opens (OAuth callback URL, OAuth client ID, OAuth client secret). OAuth passthrough is not available through OneMCP.
- Add local CLI MCP -> Add MCP server > "Local package (CLI MCP)" > "Import a local MCP package" (a package
  definition you reviewed). Steps: Import > Review & approve > Configure access. Tools start disabled.
  Ready-made packages (Filesystem, Git, Playwright...) are approved from the Library instead.
- Add REST API as MCP -> Add MCP server > "API" > Name, Slug, Base URL, "Connection route": Public internet /
  Via Remote Connector: <name>, Description > OpenAPI spec (None/URL/Upload/Paste; URL can be fetched over the
  selected Remote Connector) or generic mode (api_get/post/put/patch/delete) > "API docs for the model" >
  Credentials > Tools & access (allow/deny path rules, per-operation Auto/On/Off, Test a request) > create.
  Steps: Connection > Credentials > Tools & access > Registered
- Connect private MCP or REST API -> Remote Connectors (drawer "Remote Connectors") > New remote connector >
  Name, Description > Create connector > copy qrc_... token and run quilr-connector; then select
  "Via Remote Connector: <name>" under "Connection route" when adding a Remote server or API
- Install from catalog -> Library (drawer "MCP Library", ~439 MCPs) > "Search by name or what it does", filters
  Status / Type / Sign-in > Install, Set up or Continue setup (OAuth apps ask client ID/secret, show callback URL)
- Handle user install requests -> Library > "Pending install requests" > Install or Dismiss
- Connect OAuth server -> banner Review all, or card "Connect OAuth", or Configure > General
- Pick OAuth scopes -> Configure > Permissions (only on OAuth servers with selectable scopes, e.g. Microsoft
  Office 365 V3): tick scope groups, "Grant all (default)". Users keep their old grant until they reconnect
- Enable/disable server -> card toggle (or Configure > General header toggle)
- Delete server -> card Uninstall, or Configure > General > Danger zone > Uninstall MCP
- Turn tools on/off -> Configure > Tools ("Exposed to agents", grouped Read-only / Write / Destructive)
- Require confirmation per tool -> Configure > Tools > "Require confirmation" + "Require justification"
  (turning confirmation on also turns justification on)
- Tool drift watch -> Configure > Tools > "When the upstream tool list changes": Tell me about changes (default)
  / Update tools automatically / Don't watch this MCP; Check now; pending New/Gone > Approve or Dismiss.
  Per-user sign-in servers say "refresh it from the console"; Quilr checks hourly
- Guardrails (DLP/adversarial) -> Configure > Guardrails > Data risk / Adversarial categories, actions
  block / redact / partial-redact / monitor, separate Request (tool arguments) and Response (tool results), Default action
- Token saving -> Configure > Token saving > smart JSON compression, HTML to text, Markdown to text, text compression
- Shorter tool lists -> Configure > Tool list > "What AI apps get": List most-used tools / Add Code mode (both off
  by default) > Save tool list; Preview card (tokens per turn before -> after, Listed in full, "N tools one search
  away" with Pin, Refresh usage). Page card "Savings opportunity" > Review (drawer "Send AI apps shorter tool lists":
  Open settings / Turn on). Savings: Overall analytics > Servers & tools > "Tool list savings"
- Fix wrong tool inputs -> banner Review fixes (drawer "Review quick fixes": Show example, Apply, Dismiss,
  Apply all) or Configure > Input aliases
- Per group/user overrides -> Configure > Group & User Rules > rule applies to A smart group / A single user;
  tool, guardrail, token saving overrides (Inherit/On/Off), confirmation, justification; "Effective settings preview"
- Allow/deny by agent, smart group, user -> Configure > General > Access control (Allowed agents, Allowed /
  Denied smart groups, Allowed / Denied users; denied users take precedence)
- Forward identity to upstream -> Configure > General > "Forward user claims" (X-User-Claims header; non-OAuth servers)
- Web Search (ZIA) policy -> QuilrAI Web Search > Configure > General > Web Search policy: ZIA check timeout,
  ZIA URL overrides (one URL or domain per line), Groups with domain exclusions.
  Tenant ZIA creds -> "..." > ZIA integration (ZIA base URL, API key, Admin username, Admin password > Connect ZIA)
- API MCP rules after creation -> Configure > API (base URL, connection route, spec, rules)
- Direct-connection tokens -> Configure > API tokens (not on OAuth servers; e.g. QuilrAI Web Search) >
  "Create a token": Token name + Agent (Add agent registers a custom one) > Create token; Tokens table with Revoke.
  Clients send the token in Authorization plus their own mcpuser email header
- Which clients may connect -> Allowed Agents (matched by User-Agent keyword; open an agent to pick servers; Add agent)
- OneMCP settings -> OneMCP endpoint (dialog "OneMCP") > Dynamic tool calling (User preference / Always on /
  Always off); Memories > "Memories enabled" switch (OneMCP and workflow agents)
- Analytics -> Overall analytics (full-page Insights above). Logs -> server Inspect > Logs.
- Gateway Tool updates -> header Tool updates or Review tool updates banner. Gateway setting:
  New tools wait for approval; per-server choice under Settings > Tools. Review changes before approving.
- Who is connected (per user per MCP) -> "..." > Connections (Users, MCPs, Connected, Tool calls; "MCP users" table)
- Rejected requests -> workspace Health: REJECTED REQUESTS, ACCESS DENIED, AUTH CHALLENGES, TOKEN-AUTH REQUESTS,
  OAUTH REFRESHES, UPSTREAM SERVER ERRORS; Rejection reasons, Upstream server errors, Recent rejections (gateway-wide)
- One server's logs -> card Inspect > Logs
- Server inventory/usage -> card Open in Inventory, or sidebar Inventory (filter asset type MCP server)

POLICY ENGINE (MCP)
- Workspace: /policy/engine/mcp-gateway. Header: POLICY ENGINE ON, Updated time, More.
- Sections: Controls | Policies | Test | History.
- Controls groups and areas:
  Who can connect?: MCP Server Access, OneMCP Features, Web Search Security, Claims Forwarding.
  Which tools are available?: Invocation & Discovery.
  What can run?: Human Confirmation, Usage Quotas & Concurrency, Data & Adversarial Risks.
  What may return?: Token Savings.
- Open an area > read What happens today, defaults and How rules combine > recipe or blank rule >
  Applies to > outcome > Reads as > Save to draft > Review & publish. Most panels: Controls | Activity.
- MCP Server Access: Server access, Hidden from OneMCP. Connection permission does not by itself allow tools.
- Invocation & Discovery: Tool calls, Resource reads, Prompt fetches; inspect list/call/result steps.
  Hiding from discovery alone does not refuse a call by name. No matching allow denies the step.
- Access: highest numeric priority wins; Deny wins ties. Human Confirmation uses priority with stricter ties.
- Human Confirmation replaces the old Human Approval control label; Confirmation required section,
  including explicit exemptions that must outrank a requirement.
- Data & Adversarial Risks: Detection rules | Scan profile. Detection action applies to a whole call/result;
  per-category scan profile actions and detector selection have separate combination rules.
- Usage Quotas & Concurrency: Call quotas, Simultaneous calls. Policy-only.
- OneMCP Features: Dynamic tools, OneMCP memory, Most-used tools listed, Scripts.
- Token Savings: Smart JSON compression, HTML to text, Markdown to text, Text compression, Strip base64 content.
  Stripping encoded content makes it unavailable to the model; it is replaced with a size note.
- Web Search Security: Excluded domains, Result domains, URL overrides and timeout.
- Claims Forwarding: Forward user claims.
- Policies: Search policies, Filters, policy details, Add rule, Edit technical source.
- Test: Try a situation | Replay activity; check the rule-set label.
  Try a situation: What is happening?, Person, MCP server, Tool, More details, Add detail > Run test.
  Replay activity: Time range, Advanced replay options > Run check. Neither changes live traffic.
- History: published Versions, actor/reason, Previous version/Live version comparison, changes,
  Technical details/source/diff. Restore republishes as a new version.
- Panel links use ?tile=<id>&tab=controls or activity. Observed ids: server-access, onemcp, web-search,
  claims-forwarding, invocation, human-approval, usage-limits, data-risks, token-saving.
- Governed per-server Tools, Guardrails, Token saving, Tool list and Group & User Rules show
  Controlled by Policy Engine. Edit anyway changes stored classic values, not published policies.

RELATED PAGES
- Findings & Interactions (/interactions): MCP filter fields: MCP server, tool, agent, called via, auth mode,
  input DLP, output DLP, session
- Costs & Savings (/costs-savings): source/channel "mcp" (URL ?channels=mcp)
- Data Retention: Settings > Data management; only LLM Gateway is configurable today.
  Console retention controls for MCP Gateway and other sources are releasing soon.
- Export Center: Settings > Data management (includes MCP usage presets)
- Skills Library / Workflow Agents: Settings > AI Gateway (skills list MCP dependencies; agents pick MCP tools)
- Self Service (/self-service): end users link local MCP tools ("Connect your AI app")
- Audit: Settings > Organization > Audit Logs
- Settings > Organization > API keys: card "MCP Gateway management keys" (Management API On/Off, Active keys,
  Revoked or expired) > Manage management keys opens the Management API tab

GOTCHAS
- Drawer radio cards (placement, auth mode): click the card label/title, not the hidden input
- Buttons may be disabled when management is not enabled for the tenant or the role lacks MCP permissions
- Settings tab needs exactly one server; with none it says "Choose one server to configure"
- Sections vary by server: API only for API MCPs; Permissions only for OAuth servers with selectable scopes;
  API tokens and Forward user claims not on OAuth servers; Web Search policy only on QuilrAI Web Search
- Configure edits are drafts; Save settings in the sticky footer before closing
- Health ignores the server picker
- OneMCP opens as a centered dialog, other manage views as side drawers
